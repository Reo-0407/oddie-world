# 오디 월드 — 기획서

작성일: 2026-11-02
이 문서는 `2026-11-02-pokemon-battle-game-design.md`를 대체한다. 포켓몬 대신 「Catch an Oddie」의 오디 165종을 쓰고, 탐험 화면을 3D 월드로 바꿨다. 오디의 능력(타입, 능력치, 기술)은 `2026-11-02-oddie-battle-design.md`에 있다.

목적: 학교 학기말 활동. 약 한 달 뒤 시연(날짜 미정).
성공 기준: 시연 때 친구 두 명이 각자 기기로 접속해 자기가 키운 오디로 끝까지 대전할 수 있다.

## 1. 게임 한 줄

3D 월드를 걸어 다니다가 돌아다니는 오디에게 다가가 결투를 신청하고, 이기면 로프를 던져 잡고, 키워서 친구와 겨룬다.

## 2. 플레이 흐름

1. 아이디와 비밀번호로 가입한다.
2. 스타터 오디 3마리(Pippo, Emberi, Bubblit) 중 하나를 고른다.
3. 3D 월드에서 캐릭터를 움직인다. 월드 곳곳에 야생 오디가 돌아다닌다.
4. 오디에게 가까이 가서 버튼을 누르면 결투가 시작된다. 오디도 플레이어를 발견하면 다가와 결투를 건다.
5. 배틀은 3D 장면에서 메뉴로 진행한다. 이기면 경험치와 돈을 받고, 로프를 던져 잡을 수 있다.
6. 오디를 키우고(레벨업, 새 기술) 상점에서 로프와 회복약을 산다.
7. 언제든 친구와 방 코드로 대전해 랭킹 점수를 올린다.

## 3. 월드

- **맵은 하나로 시작한다.** 마을(상점, 회복소)과 풀숲 지역 몇 개로 이루어진 작은 맵이다. 지역은 오디 지역(초원, 사막, 얼음, 화산...)에 대응하며, 시간이 남으면 하나씩 늘린다.
- **시점은 캐릭터 뒤 3인칭이다.** 이동은 PC는 WASD, 폰은 화면 조이스틱이다.
- **오디는 월드에서 걷고 멈추며 돌아다닌다.** 모델이 움직이지 않으므로 몸을 숨 쉬듯 늘이고 통통 튀게 하는 동작은 코드로 만든다.
- **동시에 보이는 오디는 15마리 안팎이다.** 폰 성능과 용량 때문에 먼 오디는 지우고 필요한 모델만 불러온다.

## 4. 배틀

- 턴제 1:1, 메뉴로 행동을 고른다. 공격, 가방(로프, 회복약), 교체, 도망.
- 화면은 3D 장면이다. 양쪽 오디가 서 있고 카메라가 천천히 움직인다. 기술 연출은 간단한 이펙트로 한다.
- 엔진은 순수 TypeScript로 유지하고(`src/engine`), 화면과 분리한다. 서버 대전도 같은 엔진을 쓴다.
- 기술은 고유 효과 38종을 지원해야 한다. 능력 단계, 연타, 반동, 선공, 충전, 지연, 교대, 속박, 혼란 등이다. 구현은 구현 계획의 「엔진 확장」에서 한다.

## 5. 성장, 포획, 저장

- 경험치, 레벨업, 새 기술 습득은 이전 설계를 그대로 쓴다. 진화는 없다.
- 포획은 로프를 던져서 한다. 확률은 등급별 포획률, 남은 체력, 상태이상, 로프 종류로 정한다. 로프는 2종(기본, 튼튼한)이다.
- 팀은 최대 6마리고 나머지는 박스에 간다.
- 계정과 저장은 이전 설계와 같다. Supabase 무료 플랜으로 가입, 로그인, 저장을 하고 실제 이메일은 받지 않는다.

## 6. 친구 대전

이전 설계와 같다. 방 코드로 만나 팀에서 3마리를 골라 서버가 판정한다. 턴 제한시간 60초, 끊김 후 복귀, Elo 랭킹을 지원한다. 3D 장면은 배틀 화면과 같은 것을 쓴다.

## 7. 오디 그림과 3D 모델

- **만들기:** 로블록스 쪽 영어 설명(`oddie_prompts.py`)과 화풍 문구로 NVIDIA TRELLIS가 글에서 바로 3D 모델을 만든다. `tools/oddie_art/nv_batch.py`가 165종을 순서대로 만든다. 잘 안 나온 것은 같은 설명에 시드를 바꿔 다시 만들거나, FLUX 그림을 만든 뒤 Hugging Face의 TRELLIS로 그림에서 3D를 만든다.
- **용량:** 모델 하나가 약 1.5MB다. Blender로 줄이고 텍스처를 낮춰 오디당 약 300KB를 목표로 한다. 지금 필요한 오디만 불러온다.
- **대체 그림:** 3D가 잘 안 나온 오디는 모델의 정면 이미지를 카드로 쓴다.
- **권리:** 오디와 그 설명은 이 프로젝트 제작자의 것이다. 포켓몬의 이름과 이미지는 더 이상 쓰지 않는다.

## 8. 기술 구조

| 부분 | 선택 | 이유 |
|---|---|---|
| 화면 | React + TypeScript + Vite | 이미 만든 구조를 이어 쓴다 |
| 3D | Three.js (GLTF 로더) | 브라우저 3D의 표준이고 무료 |
| 배포 | GitHub Pages + GitHub Actions | 이미 동작한다 |
| 계정, DB, 실시간 | Supabase 무료 플랜 | 서버 함수까지 카드 없이 쓴다 |
| 대전 판정 | Supabase Edge Function | 같은 엔진을 그대로 재사용한다 |

코드는 `src/engine`(대전), `src/data`(오디, 기술), `src/game`(성장, 포획, 저장), `src/world`(3D 월드), `src/ui`(화면), `src/online`(Supabase)으로 나눈다.

## 9. 일정

오늘이 11월 2일이고 시연까지 약 4주다.

| 주 | 목표 | 완료 기준 |
|---|---|---|
| 1 | 엔진 확장, 오디 데이터, 3D 모델 생성, 월드 시제품 | 3D 맵에서 걷고, 오디에게 다가가면 배틀 화면이 열린다 |
| 2 | 포획, 성장, 상점, 3D 배틀 장면 | 잡고 키우는 한 바퀴가 돈다 |
| 3 | 가입, 저장, 친구 대전 | 기기 2대로 대전한다 |
| 4 | 마무리, 모델 정리, 친구 테스트 | 시연 가능 |

밀리면 줄이는 순서: 지역 늘리기 → 3D 배틀 연출 → 랭킹. 친구 대전은 줄이지 않는다.

## 10. 위험과 결정

- **3D 모델 품질:** 글에서 만든 모델은 모양이 어색할 수 있다. 모양이 나쁜 오디는 다시 만들고, 끝까지 안 되면 그림 카드로 대체한다.
- **폰 성능:** 3D 월드가 폰에서 느릴 수 있다. 먼 오디를 지우고 그림자와 후처리를 끄며, 느리면 오디 수를 줄인다. 실제 폰에서 일찍 확인한다.
- **일정:** 3D 월드는 작은 맵 하나로 시작한다. 지역은 시간이 남을 때 늘린다.
- **Supabase 일시정지:** 무료 프로젝트는 7일 비활성이면 멈춘다. 시연 전날 접속해 확인한다.
- **포획 도구 이름:** 몬스터볼은 포켓몬의 이름이라 쓰지 않는다. 오디 세계관의 「로프」를 쓴다.
- **저장 조작:** 야생 전투는 브라우저에서 처리해서 저장 조작을 막지 못한다. 친구 대전의 팀 검증으로 말이 안 되는 팀만 막는다.
